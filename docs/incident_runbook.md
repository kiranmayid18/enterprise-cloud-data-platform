# Data Pipeline Incident Runbook

1. Detect the failure or quality breach.
2. Assess affected datasets, users, and SLA impact.
3. Diagnose source availability, credentials, network, schema, logs, record counts, and SQL performance.
4. Recover using safe retry, watermark replay, configuration correction, rollback, or quarantine.
5. Validate counts, quality rules, freshness, and downstream reporting.
6. Document root cause, corrective action, preventive action, and follow-up technical debt.
